# Tasks: constellation (examples/constellation/)
Paths are relative to `examples/constellation/`. Specs: `docs/product/constellation/{brief,design-direction,ux,design,decisions}.md` and `examples/constellation/spec.md` (the spec wins). The wiki at `examples/wiki/` is the source of the copied core and is never edited.

These slices are a build order, not separate verify gates. The ported acceptance suite (T14) is written before the build, so verify stays red until S is done (HTTP suites). Two acceptance checks stay red until P is done: the "every ux.md data-testid appears in served HTML/JS" scan and the "`/js/graph.js`, `/js/layout.js` fall back to HTML" check. Write unit tests first within each slice. Each slice is sized for one builder in one sitting.

Builder S owns all of `src/`, `package.json`, `verify.config.json`, `public/js/titles.js`, `public/js/wikilink.js` and a minimal `public/index.html` and `public/app.css` (enough for the HTTP tests), and must be green over HTTP and unit tests alone. Builder P owns the rest of `public/` and builds against the real API. P-pure slices (T7, T8) depend only on T1 and can run in parallel with S. File ownership never overlaps, so parallel builders do not collide.
