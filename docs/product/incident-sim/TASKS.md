# Tasks: incident-sim (examples/incident-sim/)
Paths are relative to `examples/incident-sim/`. Specs: `docs/product/incident-sim/{brief,design-direction,ux,design,decisions}.md` and `examples/incident-sim/spec.md` (the spec wins; design.md wins over ux.md on engine and server details).

These slices are a build order, not separate verify gates. The acceptance tests (T17) exist from the start, so verify stays red until E and S are done (Node and HTTP suites) and then until P T10 and T11 land (static, token, contrast and served-testid checks). Write unit tests first within each slice. Every `engine/` and `core/` file needs its own unit tests (per-file coverage floor 60%, total 80%).

Ownership:
- Builder E owns `package.json`, `public/js/engine/*`, `public/js/core/{safe-json,progress,settings,daily,share,routes,testmode,scheduler-math,format}.js`, `scenarios/*.json`, `tests/tools/solve.js` and the matching `tests/*.test.js`. Green via Node tests alone.
- Builder S owns `src/*`, a minimal placeholder `public/index.html` (replaced in T10) and its tests. Green over HTTP alone.
- Builder P owns the rest of `public/` (`tokens.css`, `app.css`, `favicon.svg`, `index.html`, `core/{keys,announcer,viewmodel,layout,particles,debrief-model}.js`, `dom/*`) and builds against the real engine and server.
- A pinned outcome that proves infeasible is raised for a spec amendment, never fixed by weakening a test or a scenario class.
